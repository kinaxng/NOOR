# NOOR 架构文档

## 概述

NOOR 是一个面向 JAV 视频处理与媒体管理的本地优先 AI 平台，整合 LADA 视频修复 + Whisper 字幕生成 + GPT 翻译。

**核心功能**：
1. **LADA 视频修复** — 调用 `lada-cli` 对马赛克视频进行 AI 修复（subprocess 运行）
2. **Whisper 字幕生成** — 多 pipeline 架构，支持日语/中文/英语，支持 GPT 翻译
3. **Emby 媒体库集成** — 代理 Emby API，展示海报墙、提交任务

**端口占用**：
| 端口 | 服务 | 说明 |
|------|------|------|
| 9898 | 后端 uvicorn | API 服务（systemd / docker 统一端口） |
| 5173 | 前端 vite dev | 热重载开发服务器 |

## Job 生命周期

### 1. 任务创建
```
POST /api/jobs
  → 创建 Job ORM (status=queued)
  → await job_manager.queue.put((job_id, job_data, job_type))
  → 如果 worker 未启动 → asyncio.create_task(_process_queue())
  → 返回 JobResponse (status=queued)
```

### 2. Worker 处理
```
_process_queue() [while True]
  → queue.get_nowait() 取任务
  → 更新 DB status=running
  → job_type == "lada"  → _run_lada()
    job_type == "whisper" → _run_whisper()
  → 完成后更新 DB status=completed/failed
```

### 3. 进度实时推送（SSE）
```
_run_lada / _run_whisper
  → 创建 asyncio.Queue (progress_queue)
  → 启动 progress_reader task（从 queue 读事件）
    → 写 DB job.progress
    → 写 job log 文件
    → 写 SSE event_queue
  → pipeline 推送事件到 progress_queue
  → 完成后通知 event_queue
```

### 4. 崩溃恢复（recover_queued_jobs）
```
uvicorn 启动时（lifespan）
  → 查询 DB 中 status=queued 的任务，重新入队
  → 查询 status=running 的任务，标记为 failed（崩溃残留）
```

## LADA Pipeline（视频修复）

### run_lada_restoration()

```python
async def run_lada_restoration(job_id, input_path, output_path, job_settings, progress_queue):
    # 1. 构建 lada-cli 命令（替换 -unbuffered wrapper）
    # 2. 启动 ThreadPoolExecutor(max_workers=1)
    # 3. 子线程中运行 subprocess.Popen，实时读取 stdout
    # 4. 同时启动 monitor_output_size() 协程，每 2s 轮询 .tmp.mp4 大小
    # 5. 进度上报：output_size / (input_size * 1.3) * 100
    # 6. 完成后推送所有日志行到 progress_queue
```

### 关键实现细节

- **subprocess 方式**：`subprocess.Popen` + `iter(proc.stdout.readline, b"")` 逐行读取
- **ThreadPoolExecutor**：避免阻塞事件循环，max_workers=1 保证单任务串行
- **lada-cli wrapper**：`/lada-cli` → `/lada-cli-unbuffered`（用 `python3 -u` 无缓冲输出）
- **进度估算**：`output_path + ".tmp.mp4"` 文件大小 / (input_size × 1.3)，上限 99%
- **临时文件**：lada-cli 先写 `.tmp.mp4`，完成后 rename 到最终路径

## Whisper Pipeline

### 多 pipeline 架构

```
WhisperPipeline
  ├── config.pipeline_mode 决定数据流
  │
  ├── ANIME (anime-whisper)
  │     → AudioExtractor → AnimeWhisperProcessor → enhancer → SRT
  │
  ├── FASTER (faster-whisper)
  │     → AudioExtractor → FasterWhisperProcessor → enhancer → SRT
  │
  ├── BALANCED
  │     → AudioExtractor → FasterWhisperProcessor → enhancer → merge → SRT
  │
  ├── ENSEMBLE (anime + faster 双引擎)
  │     → ANIME pipeline + FASTER pipeline → merge → SRT
  │
  ├── TRANSFORMERS / QWEN
  │     → AudioExtractor → custom processor → GPU enhancer → SRT
  │
  └── TRANSLATE-SRT
      → 读取现有 SRT → GPT 翻译 → 输出新 SRT
```

### 翻译接口（translator.py）
