## Phase 2 建议目标

如果正式进入下一阶段开发，建议目标只设为四件事：
1. 取消会真正终止底层 LADA / Whisper / 翻译执行
2. worker 生命周期保证单实例、单任务串行
3. `queued / running / cancelled / completed / failed` 状态流只保留一条权威落库路径
4. 为以上三点建立稳定回归测试

## 当前对任务系统的判断

### 已改善的部分
- LADA 子进程取消路径已有 `SIGTERM / SIGKILL` 处理和临时文件清理
- `JobManager` 已不再按 `running_job is None` 反复新建 worker
- `cleanup_orphaned_jobs()` 已有明确契约返回，前端不再靠文案猜测结果

### 仍然是 Phase 2 主风险的部分
- Whisper 目前仍运行在独立线程中，取消只是在 manager 侧设置事件并等待线程自行退出，缺少真正可中断的底层执行边界
- 状态落库分散在 `_process_queue()`、`_run_lada()`、`_run_whisper()`、`_run_translate_srt()` 多个位置，维护成本高且存在竞态窗口
- Whisper 的 reader thread / pipeline thread / manager event queue 目前是多源并发更新，语义不够集中
- 现有 `test_job_manager.py` 的 worker 级异步用例在当前环境会挂起，说明测试基座本身需要先稳住
